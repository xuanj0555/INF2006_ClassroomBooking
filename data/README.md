# Roomly Data Documentation

## Purpose

Roomly uses two separate categories of data:

1. Historical university-library reservation data for descriptive reservation-demand analytics.
2. Live application data for the Roomly booking system.

The historical dataset is not inserted into the live booking tables. Historical reservations do not establish attendance or physical occupancy.

## Raw-to-Cleaned Processing

The preparation script is:

`data/prepare_reservations.py`

It performs the following steps:

1. Loads the raw CSV.
2. Preserves room identifiers as text.
3. Parses start and end timestamps.
4. Checks for missing or invalid timestamps.
5. Checks for missing room identifiers.
6. Checks for exact duplicate source rows.
7. Calculates duration from the start and end timestamps.
8. Excludes durations below five minutes.
9. Excludes durations above 240 minutes.
10. Rounds retained durations to the nearest whole minute.
11. Derives date, weekday, start hour, month and weekend fields.
12. Writes the cleaned CSV.

These duration thresholds are analytics cleaning rules, separate from the live application's booking rules.

### Exclusion Counts

| Check or cleaning rule | Rows excluded |
|---|---:|
| Invalid timestamps | 0 |
| Missing room identifiers | 0 |
| Exact duplicate rows | 0 |
| Duration below five minutes | 1 |
| Duration above 240 minutes | 506 |
| **Total excluded** | **507** |

Therefore:

51,826 raw records − 507 excluded records = 51,319 cleaned records.

The excluded short reservation had a timestamp-derived duration of three minutes, although the raw duration field stated five minutes. The processing uses timestamps as the duration source.

## Reproduction

Run commands from the repository root using an activated Python environment with the dependencies installed.

Install dependencies:

`python -m pip install -r analytics/requirements.txt`

Run dataset preparation only:

`python data/prepare_reservations.py`

Run the complete preparation and analytics workflow:

`python analytics/reproduce.py`

The complete workflow regenerates the cleaned dataset, executes the notebook and checks that the four expected output files exist.

Full environment setup instructions are in [analytics/README.md](../analytics/README.md).

## Known Limitations

- The source timezone is unspecified. Historical timestamps are treated as timezone-naive source-local values without conversion to Asia/Singapore.
- Reservations do not prove attendance or physical occupancy.
- The historical dataset contains no user identities, participant lists, booking-creation timestamps, cancellation outcomes or unsuccessful booking attempts.
- Nine dates within the observed period have no reservation starts. The cause may be closures, zero demand or missing data.
- Two overlapping reservation cases were retained because there was insufficient evidence to identify incorrect records.
- Overlaps may inflate reserved-hour totals.
- The 507 duration exclusions mean the cleaned dataset does not represent every raw record.
- Historical room identifiers are separate from the fictional rooms in the live prototype.
- The source-page total differs from the measured raw-file count by one; the cause is unverified.
- The results describe the supplied 2024 dataset and do not establish current or future demand.
- No forecasting or no-show prediction model is included.
